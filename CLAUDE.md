# Sofabelle CRM Digest Bot

Telegram-бот: отчёты по расписанию из CRM mefi (лиды → оферты → контракты) в управленческую группу Sofabelle + ответы на вопросы по тем же данным в чате. Первый тенант будущего продукта Davoq «Asistent CRM».

## Обязательно прочитать перед работой

- `docs/PLAN.md`: где мы, что дальше, принятые решения.
- `docs/INDEX.md`: легенда репозитория; остальные файлы читать только по колонке «когда читать».

## Экономия контекста

- Читать только файлы из строки чтения промпта.
- `pytest -q --tb=short`, ruff и git без verbose.
- Context7 только для конкретной сигнатуры, один запрос на один вопрос.
- Не выводить содержимое файлов в чат, результат это коммит.
- Итог сессии писать в `docs/PLAN.md`.
- git status из песочницы может показывать detached HEAD, это ложная тревога; перед сообщением о ней проверить `git branch --show-current`.

## Язык

Код, идентификаторы, коммиты — английский. Комментарии (только WHY), документация, ADR, сообщения в служебный бот — русский. Тексты отчётов для группы — румынский (RO) и русский (RU), шаблоны в `templates/`. Названия статусов, шоурумов, источников — как в mefi (`Clienți`, `NU A RASPUNS`, `București`), никогда не переводить и не нормализовать регистр в данных.

## Архитектурные инварианты

1. **Один расчёт — один источник истины.** Каждая метрика — функция в `metrics/`. Её вызывают и отчёты по расписанию, и режим вопросов в чате. Цифра в дайджесте и в ответе на вопрос совпадает по построению.
2. **LLM не считает.** В режиме вопросов модель только выбирает инструмент и параметры (enum: период, шоурум, менеджер). Инструмент считает, модель формулирует. Каждый ответ содержит период и вызванную функцию. Без вызова инструмента модель не отвечает цифрами.
3. **Отчёты читают из Postgres, не из API.** Ежедневный полный снапшот лидов; `status_changed_at` в mefi хранит только последнее изменение, история воронки восстанавливается только из снапшотов.
4. **Маппинг статусов — конфиг.** Неизвестный `status.name` → категория `UNMAPPED`, считается отдельно, алерт в служебный бот. Никогда молча не отбрасывать.
5. **Модуль отчёта = id + источники + enabled + функция + шаблон RO/RU.** Новый отчёт — новый модуль в реестре, а не правка бота. Модуль с неподключённым источником нельзя включить через `/settings`.
6. **Сбой источника не блокирует отчёт.** Отчёт уходит с пометкой «данные [источник] недоступны»; ошибка — в служебный бот.
7. **В группу — только агрегаты и имена сотрудников.** Телефоны, e-mail, тексты заметок клиентов не выводятся ни в отчётах, ни в ответах чата.

## Ловушки mefi API (`leads:read`)

- Пустой body `POST /leads/search` → только `lifecycle: active`. Всегда передавать `["active","lost","junk"]`. Lifecycle для классификации не использовать: все лиды со статусом, включая IRELEVANT и NU A RASPUNS, в mefi `active` (проверено 24.09.2026, `docs/mefi-api-notes.md`). Категория — только по `status.name`.
- `date_field` ∈ {created_at, last_contact_at, status_changed_at}; `converted_at` фильтруется на своей стороне.
- `estimated_value` = null при 0 и продавцами не заполняется. Деньги только из Oferte/Contracte (источник B).
- Кастомное поле `Ofertat` (field_id 20) — select `"✅DA"` / `"❌NU"`, без даты.
- Шоурум — `custom_fields[field_id=14, name="Showroom"]`, не `location.city` (там город клиента).
- Неверный ключ фильтра → 422.
- Реальный лимит ~1 req/s по IP (burst 10 / 10 с), а не 600/мин токена. Заголовки `X-RateLimit-*` показывают только лимит токена, по ним темп не подбирать. Пауза ≥ 1.2 с между любыми запросами, глобально на процесс; 429 → ждать `Retry-After` и повторить, прогон не валить.
- `POST /leads/search` отдаёт полные карточки с `custom_fields`, `GET /leads/{id}` не нужен (проверено 24.09.2026).
- Заметки недоступны: скоуп `leads:read:notes` у mefi не выпущен. `last_contact_at` при создании = `created_at` и перезаписывается последним касанием; `status_changed_at` = null, если статус задан при создании.
- Источник id 7 в mefi называется `Arhirtect` (опечатка mefi) — писать так.

## Окна времени

Таймзона расчётов — `Europe/Bucharest`, всегда явно. Ежедневное окно: 19:00 вчера → 19:00 сегодня. Недельный счёт лидов: время в [10:00, 19:00) по Бухаресту → текущий день, любое другое → следующий календарный день; источник Showroom исключён (проверено по ручным отчётам за июль 2026).

## Секреты

Только через переменные окружения (`.env.example` — список). Пароль сервисного пользователя mefi, токены ботов, ключ Anthropic — никогда в репозитории, логах, сообщениях в Telegram. Сервисный пользователь mefi — read-only, скрипт делает только GET и логин.

## Рабочий процесс

- Фича: `/rigorous shape` → согласование → `/rigorous craft` → `/rigorous critique` → `/rigorous harden`.
- Формулы KPI покрыты тестами на эталонном месяце (`tests/fixtures/etalon-2026-05.json`), сверенном вручную с mefi. Изменение формулы = ADR + обновление эталона.
- Перед коммитом: typecheck/lint, тесты. Перед первой отправкой в реальную группу — прогон в тестовой группе с `DRY_RUN=1`.
- Необратимое (drop таблицы, удаление снапшотов, смена chat_id продовой группы) — подтверждать с пользователем.

## Чего не делать

- Не тянуть text-to-SQL, PandasAI, Vanna, агентные фреймворки. Решение принято, см. `docs/research.md` §4.
- Не хардкодить статусы, шоурумы, пороги в коде.
- Не выводить персональные данные клиентов.
- Не писать в mefi ничего, кроме логина.
- Любой вызов mefi кроме GET и POST /leads/search запрещён, включая отладку в Bash.
- Не добавлять feature-флаги вне реестра модулей.
- Не выводить содержимое `docs/reference/` в чат и не читать его через Read. Папка в `.gitignore`, там исходные файлы клиента с данными лидов. Читать только скриптом, который печатает структуру, счётчики и агрегаты; эталон в `tests/fixtures/` обезличен.
