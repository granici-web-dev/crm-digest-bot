## Форма ответа

Search, как у лидов:

```json
{ "success": true, "request_id": "…", "data": [ ... ],
  "meta": { "page": 1, "per_page": 100, "total": 797, "total_pages": 8 } }
```

GET заворачивает карточку в `client`, а не в `data`:

```json
{ "success": true, "request_id": "…", "client": { ... } }
```

Заголовки `x-ratelimit-limit/remaining/reset` и `x-request-id`, как у лидов. `remaining` у ключа clients свой (599 → 594), IP-лимит по документации 60/мин общий, в заголовках не виден. Правило паузы 1.2 с глобально на процесс остаётся в силе и должно покрывать оба ключа.

## Выгрузка

Проверка 28.09.2026, 10 вызовов `POST /clients/search`, пауза 1.3 с, ни одного 429.

- Листание `sort: created_at asc` по 100 теряет клиентов: 797 слотов, 776 уникальных id, 21 дубль. Все дубли созданы 05.02 (импорт) и стоят на стыках страниц 1/2, 2/3, 3/4, где `created_at` совпадает до секунды. У mefi нет тай-брейка, порядок равных значений зависит от запрошенного окна страницы.
- Повтор той же страницы отдаёт тот же порядок: дочитывать повтором бесполезно, пропуски не сойдутся.
- `sort: name` сортирует без учёта регистра. Внутри дня импорта (`total: 474`) имена уникальны у всех 453 клиентов, попавших в выгрузку.
- Поэтому `MefiClient.search_all_clients` делит диапазон `created_at` пополам по дням, пока в диапазоне не больше 100 клиентов (одна страница, порядок не важен). Один день больше 100 листается по `name`. Равные имена на стыке страниц всё ещё могут дать пропуск, его ловит проверка полноты против `meta.total` пробного запроса. На 797 клиентах это порядка 20–30 запросов вместо 8 (оценка, живым прогоном не мерили).
- Лиды листаются по `created_at` как раньше: 28.09 записано 3045 из 3045, массовых пачек с одной секундой у лидов не видели. Если проверка полноты лидов начнёт срабатывать, лечить так же.

## Связь клиента с лидом

Эвристика: клиент и лид с `converted_at` в пределах 60 с.

- 191 из 318 клиентов после импорта спарены с лидом. Клиент создаётся **за 2–8 с до** `converted_at` лида (87 на −3 с, 77 на −2 с). Шоурум совпал у 190 из 191, `assigned_to` лида входит в `responsibles` у 147. Расширение окна до часа и до суток почти ничего не добавляет (191 → 192): пары однозначные. Смена статуса лида на `Clienți` сама создаёт клиента.
- 8 лидов с `converted_at` после импорта клиента не получили (март 4, апрель, май, июль, сентябрь по одному).
- **127 клиентов созданы без конверсии лида.** Признак: `last_contact_at = null` у 126 из 127, у спаренных 0 из 191. Больше всего в феврале–мае (19, 28, 1, 57; 15 за 08.05), с июня 2–7 в месяц. `Ofertat = ✅DA` у 125, компании и физлица поровну, больше всего у București (74). Похоже на ручной ввод прошлых контрактов после импорта; что это с июня, API не говорит.

## Вывод: Contract Cantitate = новые клиенты за окно 19:00→19:00 по шоуруму?

**Технически можно, как определение нельзя без решения владельца.**

- Можно: `created_at` в UTC с секундами, Showroom заполнен у 100 %, `state` лишь у одного клиента не active. Полная выгрузка 797 клиентов = 8 страниц ≈ 10 с; окно считать локально по снапшоту, как лиды.
- Нельзя поставить знак равенства с `converted_at` лидов: за июль–сентябрь 109 клиентов против 103 конверсий. Разница по шоурумам только у București (июль 27 против 21, август 26 против 19, сентябрь 16 против 15) и у Cluj в июле (11 против 12). Лишние это клиенты, созданные вручную без лида (`last_contact_at = null`).
- Счёт по клиентам ловит контракты без лида в mefi (если это они); счёт по `converted_at` их не видит. Счёт по `converted_at` ловит конверсии, по которым mefi клиента не создала (8 за 8 месяцев).
- Импорт 05.02 и массовый ручной ввод (08.05: 15 клиентов) в ежедневном окне дадут всплеск. Если считать по клиентам, нужен фильтр, например исключать `last_contact_at = null`, а это ровно ручные клиенты.

Вопрос владельцу: клиенты, созданные вручную без лида (2–7 в месяц с июня, в основном București), это новые контракты или ввод старых? Если новые, Contract Cantitate = новые клиенты за окно по полю Showroom, импорт исключить по дате. Если старые, оставить `converted_at` лидов (d6, ADR-004), а клиентов использовать как сверку.
