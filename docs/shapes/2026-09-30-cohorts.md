# Shape: m9 «Conversie de cohortă» и цикл сделки (30.09.2026)

Статус: согласован 30.09.2026, см. «Согласовано» в конце.

## Цель

Месячный блок m9: по шести когортам месяца создания лида видно, сколько лидов стали клиентами к дате снапшота и за сколько дней, плюс одна строка о длине цикла сделки у договоров месяца. Вывод для владельца из замера 29.09: почти все договоры когорты в первые 30 дней, медиана 3–4 дня.

## Подход

Одна функция `monthly_cohort_conversion(lead_frame, report_date, config)` в `metrics/monthly.py` (рядом с `monthly_trend`, те же `trend_months` и `month_window`), один снапшот отчёта, истории не нужно: `created_at` и `converted_at` не меняются. Процент когорты берётся из существующей `extra.cohort_conversion` (SCR когорты), поэтому процент когорты отчётного месяца в m9 совпадает с SCR компании в m4 по построению. Дни до договора = `converted_at − created_at` точной разницей aware-datetime (DST не влияет), в долях суток. Цикл месяца считается по тому же множеству, что «Contracte» последнего месяца m3 (`converted_at` в окне месяца, как `converted_count`). Пороги корзин и «быстрого» цикла в `params` модуля m9, не в коде.

### Решения по требованиям

1. **Когорта и знаменатель.** Когорта = `LEADS` месяца (окно `month_window`, без PARTNERSHIP и тестовых аккаунтов). Процент = `CLIENTI / USEFUL`, как в kpi-definitions («Когортная конверсия») и как SCR в m4, а не `клиенты / LEADS` из замера. Причина: в одном сообщении m4 и m9 иначе показали бы две разные «конверсии лидов сентября». Корзины ≤30/≤60/≤90 тоже от `USEFUL`, тогда ≤90 у зрелой когорты сходится к проценту. Замер 29.09 был от LEADS, цифры в тексте будут выше примерно на долю IRELEVANT (открытый вопрос 1).
2. **Клиент когорты** = `is_clienti` (статус `Clienți` на дату снапшота), как `CLIENTI` в m2 и m4. `converted_at` нужен только для дней: клиент без `converted_at` входит в «Cl.» и процент, но не в корзины и не в медиану; их число сноской (как m11). Лид с `converted_at`, у которого статус больше не `Clienți`, в клиенты когорты не входит, в цикл месяца входит (как в m3).
3. **Незрелая когорта, точное правило.** `возраст когорты = конец окна месяца отчёта − конец окна месяца когорты` (обе границы 19:00 последнего дня; снапшот отчёта снят в конце окна отчёта). Корзина ≤N показывается, только если `возраст ≥ N суток`: тогда каждый лид когорты прожил не меньше N суток. Иначе «—». Когорта с `возраст < max(корзин)` (90) помечается «*» у названия месяца, сноска «* lună în curs: clienții și mediana încă cresc». Для отчёта за сентябрь: Sep 0 суток (все «—»), Aug 30 (≤30), Jul 61 (≤30, ≤60), Jun 91 и старше полные. Процент и медиана у незрелых показываются всегда: это факт на сегодня, сноска объясняет смещение.
4. **Цикл месяца.** Договоры с `converted_at` в окне отчётного месяца: число, медиана дней, 75-й процентиль (`Series.quantile(0.75)`, линейная интерполяция pandas, записать в kpi-definitions), доля с днями ≤ 7. Договоров нет → «—». В тексте одна строка под таблицей.
5. **Шоурумы.** В тексте нет: при 14–35 клиентах в месяц на три шоурума медиана по 5–12 значениям это шум, а процент шоурума для отчётного месяца уже есть в m4. Полная разбивка на новом листе Excel m19 «Cohorte». Шоурум лида на дату снапшота, строки как `showroom_keys` (конфиг, чужие значения, «без шоурума»).
6. **Эталон.** В `tests/fixtures/etalon-2026-05.json` нет `converted_at` (0 из 314 лидов, ключа нет в строке лида). Когорту мая в эталон не добавляем; вместо этого синтетические unit-тесты с известными датами (ниже). Пересчёт майской когорты для сверки делается разово скриптом по снапшоту на этапе craft и пишется в PLAN как замер, не как эталон.
7. **Ограничения** в kpi-definitions: клиент без `converted_at` в корзинах и цикле не виден (сейчас 1 случай); лид, удалённый из mefi, выпадает из когорты задним числом, и старая когорта в следующем отчёте может уменьшиться; источник и шоурум когорты на дату снапшота.

## Сигнатуры

```python
# metrics/monthly.py
@dataclass(frozen=True)
class CohortRow:
    month: date
    counts: LeadCounts                       # LEADS-когорта, из lead_counts
    clients_with_date: int                   # is_clienti и converted_at not null
    clients_within_days: dict[int, int | None]  # N → клиентов с днями ≤ N; None = корзина незрелая
    median_days: float | None
    age_days: float
    in_progress: bool                        # age_days < max(корзин)
    conversion: float | None                 # property: extra.cohort_conversion == kpis_from(counts).scr
    def share_within(self, days: int) -> float | None   # ratio(clients_within_days[N], counts.useful), None для незрелой

@dataclass(frozen=True)
class DealCycle:
    contracts: int
    median_days: float | None
    p75_days: float | None
    within_fast_days: int
    share_within_fast: float | None          # property, ratio

@dataclass(frozen=True)
class MonthlyCohortConversion:
    report_month: date
    cohorts: tuple[CohortRow, ...]           # 6, от старой к отчётной
    cohorts_by_showroom: dict[str | None, tuple[CohortRow, ...]]
    cycle: DealCycle
    cycle_by_showroom: dict[str | None, DealCycle]
    clients_without_converted_at: int        # по шести когортам

def monthly_cohort_conversion(lead_frame, report_date, config) -> MonthlyCohortConversion
```

Параметры m9 в `config/modules.yaml`: `params: { age_buckets_days: [30, 60, 90], fast_cycle_days: 7 }`, модель `CohortConversionParams` в `config.py` (как `ScrLevelsParams`), корзины по возрастанию, валидация при загрузке. Будущий инструмент чата вызывает ту же функцию; в этом shape инструмент не добавляется.

## Альтернативы (отвергнуты)

- **Процент от LEADS, как в замере.** Проще объяснить, но расходится с SCR m4 в том же сообщении и с формулой kpi-definitions; смена формулы = ADR. Оставлено открытым вопросом 1.
- **Клиент = `converted_at not null`, без статуса.** Честнее для дней, но даёт третье определение клиента рядом с m2/m4 (статус) и m3 (converted_at в окне). Выбрано: статус для счёта, дата только для дней.
- **Корзины как доля от клиентов когорты** (34 из 41 = 83 % за 30 дней): ярче показывает вывод владельцу, но у незрелой когорты даёт ложные 100 %. Можно добавить строкой-выводом позже, если владелец попросит.
- **Когортная кривая по историческим снапшотам** (как пример в report-menu: 8,9 % на 31.07 → 12,4 % на 31.08): требует снапшот на конец каждого месяца, история начинается с 16.09; вернуться, когда наберётся 3 месячных снапшота.

## Риски

- `converted_at < created_at` (клиент заведён раньше лида, лид создан задним числом): отрицательные дни попадут в ≤30 и потянут медиану вниз. В craft шаг 0: посчитать такие лиды на снапшоте; если есть, отдельное решение (не обрезать молча).
- Удалённые из mefi лиды меняют старые когорты задним числом: цифра прошлого отчёта может не совпасть с новой. Сноски в тексте нет, строка в kpi-definitions.
- Медиана по 14–35 значениям скачет от месяца к месяцу; поэтому без разбивки по шоурумам в тексте.

## Открытые вопросы

1. Знаменатель процента и корзин: `USEFUL` (рекомендую, совпадает с m4) или `LEADS` (как замер 29.09, требует ADR и расхождение с m4 в одном сообщении)?
2. Порог «быстрого» цикла 7 дней и корзины 30/60/90 оставить? При медиане 3–4 дня возможно информативнее ≤7/≤30/≤90.
3. Пример в report-menu (кривая по снапшотам) заменить на новую таблицу, согласны?

## Согласовано (30.09.2026)

1. Знаменатель процента и корзин `USEFUL`, как в m4 и kpi-definitions. Клиент когорты по статусу `Clienți`, `converted_at` только для дней.
2. Корзины ≤7 / ≤30 / ≤90 дней (`params` m9: `age_buckets_days: [7, 30, 90]`), порог «быстрого» цикла 7 дней. Колонка ≤N показывается при возрасте когорты ≥ N суток, иначе «—»; когорта младше 90 суток помечена «*» со сноской. Шапка таблицы: `Luna Lead Cl. % ≤7 ≤30 ≤90 Zile`.
3. `converted_at` раньше `created_at` → дни = 0 (договор в день обращения). Замер первым шагом на снапшоте 29.09: 0 таких лидов из 202 с `converted_at` (196 `Clienți`), порог 2 % не задет.
4. Шоурумы только на листе Excel m19 «Cohorte»; в тексте таблица когорт и строка цикла сделки.
5. Пример m9 в `report-menu.md` заменяется на новую таблицу; пример «în lucru» в `test_settings_menu` на y1.
6. Эталон не меняется (`converted_at` в фикстуре нет); синтетические тесты по тест-плану.
