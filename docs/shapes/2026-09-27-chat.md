# Shape: режим вопросов в группе (27.09.2026)

## Goal

Руководитель пишет в группе «@bot câte oferte am avut săptămâna asta în București?» и получает reply по-румынски с цифрами из тех же функций `metrics/`, что отчёты, и курсивной подписью: период, снапшот, вызванная функция.

## Approach

Отдельный `Router` в том же диспетчере, что `/settings` (бот отчётов, long polling уже есть). Ручной tool-use цикл на `AsyncAnthropic`: модель выбирает один из 6 инструментов, аргументы проходят pydantic с enum из конфига, инструмент это тонкая обёртка над существующей функцией `metrics/`, результат уходит модели как JSON только из агрегатов, имён сотрудников и шоурумов. Подпись и отказы строит код, а не модель: инвариант 2 держится на коде, промпт только помогает.

Инвариант 1 по построению: у каждого инструмента нет своей арифметики, только выбор окна, выбор кадра и выбор строки из результата функции `metrics/`. Окна именованных периодов собираются из `daily_window`, `weekly_window`, `month_window` в новой чистой функции в `metrics/`.

## Решения

**Периоды.** `metrics/chat_periods.py`: `named_period_window(name, today, time_settings) -> Period`, `today` = календарный день по Бухаресту.
- `azi` = `daily_window(today)`; `ieri` = `daily_window(today − 1)`.
- `saptamana_curenta` = [`daily_window(понедельник).start`, `daily_window(today).end`); в воскресенье совпадает с `weekly_window(today)` (w3).
- `saptamana_trecuta` = `weekly_window(прошлое воскресенье)`.
- `luna_curenta` = [`month_window(today).start`, `daily_window(today).end`); `luna_trecuta` = `month_window(последний день прошлого месяца)`.
- `ultimele_30_zile` = [`daily_window(today − 29).start`, `daily_window(today).end`).

**Кадр (снапшот).** Отступление от п. 4 ТЗ, подтверждено (ответ 1).
- Текущие периоды (`azi`, `saptamana_curenta`, `luna_curenta`, `ultimele_30_zile`) и `overdue_followups`, `untouched_leads`: последний успешный снапшот.
- Закрытые периоды (`ieri`, `saptamana_trecuta`, `luna_trecuta`): снапшот на дату конца периода, тот же, по которому ушёл отчёт. Иначе когорта прошлой недели «дозревает», а потери прошлого месяца теряют лиды со сменой статуса: цифра в чате разойдётся с уже отправленным w3/m2/m8. Снапшота за эту дату нет: инструмент возвращает «нет данных за дату X», без подмены другим днём.
- Окно начинается не раньше конца окна снапшота (спросили «azi» в 12:00, снапшот вчерашний): «данных за этот период ещё нет», а не нули.
- Окно покрыто частично: результат несёт `data_as_of`, подпись говорит «date din snapshotul din 26.09.2026».

**Инструменты** (`src/digest/chat/tools.py`, описания для LLM в `config/chat_tools.yaml`, RO):
| Инструмент | Функция `metrics/` | Результат |
|---|---|---|
| `funnel(period, showroom?)` | `lead_counts` / `lead_counts_by_showroom` + `kpis_from`; `converted_count` / новая `converted_count_by_showroom` | счётчики, KPI, контракты |
| `manager_kpi(manager, period)` | строка `manager_cockpit_table` (m5) | счётчики, 9 KPI, цель выполнена да/нет |
| `compare_periods(metric, period_a, period_b, showroom?)` | два вызова как в `funnel` + `period_delta` | два значения и изменение |
| `loss_reasons(period, showroom?)` | `loss_reasons_in_window` | ключи причин с `label`, счёт по шоурумам |
| `overdue_followups(manager?)` | `overdue_revenire_by_manager` | группы по консультанту |
| `untouched_leads()` | `untouched_leads` | группы по консультанту |

`metric` enum = `COUNT_NAMES` + `KPI_NAMES` + `contracts`. `manager` enum = имена с `active: true` и без `test_account`; `showroom` enum = `status_mapping.showrooms`. Схемы строятся из конфига при старте, `strict: true`, `additionalProperties: false`. Проценты и доли приходят модели уже отформатированными фильтрами `reports/render.py` (`"23%"`, `"—"`), чтобы модель копировала строку, а не пересчитывала. Сериализация результата: явный белый список полей, не `asdict`: ни id лидов, ни `raw`, ни контактов.

**Цикл** (`src/digest/chat/loop.py`): `AsyncAnthropic(timeout=30, max_retries=2)`, модель `ANTHROPIC_MODEL` (по умолчанию `claude-sonnet-5`), `max_tokens=600`, `thinking={"type": "disabled"}` (иначе рассуждение съедает бюджет в 600 токенов, см. «Tradeoffs»), `tool_choice=auto`. Не больше 3 выполненных вызовов инструментов на вопрос; лишний `tool_use` получает `tool_result` с `is_error`, последний раунд идёт с `tool_choice={"type": "none"}`. Ошибка аргументов (pydantic) это `is_error` с текстом ошибки, в счёт 3 входит.

**Страж цифр** (инвариант 2 кодом):
- Ни одного успешного вызова инструмента, а в тексте есть цифра: текст не отправляется, уходит шаблонный отказ из `templates/chat_refusal.j2` (вежливо, примеры вопросов без цифр), статус `blocked_numbers`.
- Без инструмента и без цифр (вопрос вне данных, уточнение «которого консультанта?»): текст модели отправляется, подписи нет, статус `no_tool`.
- С инструментом: каждое число в ответе должно встречаться среди разрешённых: числа из результатов инструментов, из текста вопроса, даты и годы из подписи периода. Не нашлось: ответ не отправляется, отказ «nu pot formula un răspuns exact», статус `unverified_numbers`, алерт в ops с вопросом, инструментами и ненайденным числом (ответ 2).

**Подпись** строит код: `<i>Perioada: 22.09–27.09.2026 (saptamana_curenta) · funnel(showroom=București)</i>`, по строке на вызов; при несегодняшнем снапшоте строка `<i>Date din snapshotul din 26.09.2026</i>`. Текст модели экранируется, `parse_mode=HTML`.

**Триггер** (`src/digest/bot/chat_handlers.py`): сообщение в чате `TELEGRAM_TEST_CHAT_ID` или (`TELEGRAM_GROUP_CHAT_ID` и `DRY_RUN=0`), и либо entity `mention` с `@<username бота>` / `text_mention` с id бота, либо reply на сообщение бота. Остальное молча игнорируется и не логируется. Ответ `message.reply`. Боту в группе нужен выключенный privacy mode в BotFather, иначе упоминания не доходят; шаг в `docs/deploy.md`, проверка в тестовой группе.

**Предохранители.**
- Включение: ключ `chat_enabled` в таблице `settings`, дефолт `chat.enabled` из `modules.yaml`. В `/settings` четвёртая кнопка «Chat» с одним переключателем; строка в ops «было → стало», как у модулей. Без `ANTHROPIC_API_KEY` переключатель серый «fără cheie API» и не пишется (как модуль с неподключённым источником).
- Лимит: 30 вопросов в день по Бухаресту на `chat_id` (считаются строки `chat_questions` кроме `rate_limited`), 31-й получает вежливый отказ, строка со статусом `rate_limited`. Параллельные вопросы могут дать 31–32: принимаем.
- Сбой API (`anthropic.APIError`: статус, соединение, таймаут), `stop_reason` `max_tokens` или `refusal`: reply «Nu pot răspunde acum, încercați mai târziu.», алерт в ops через `describe_error`, статус `api_error` / `max_tokens` / `refusal`.

**Конфиг и настройки.** `Settings`: `anthropic_api_key: SecretStr | None`, `anthropic_model: str = "claude-sonnet-5"`. `modules.yaml` `chat.tools` = шесть имён, валидатор: подмножество реализованных инструментов (реестр, как `IMPLEMENTED_MODULES`), `chat.daily_question_limit: 30`. Системный промпт `templates/chat_system.md` (RO): отвечать только по-румынски, числа только из результатов инструментов, без инструмента цифр нет, вне данных вежливый отказ с примерами. Зависимость `anthropic` в `pyproject.toml` (в STACK.md уже есть).

## Tradeoffs / alternatives considered

- **Всё из последнего снапшота (буквально п. 4 ТЗ).** Проще, один кадр на вопрос. Отвергнуто: «сколько оферт на прошлой неделе» разойдётся с w3, отправленным в воскресенье, и с m8 по потерям. Главный риск проекта это разные цифры для одного вопроса.
- **Отказ вне данных всегда шаблоном, текст модели без инструмента не отправлять никогда.** Строже, но бот не сможет переспросить «которого консультанта?». Выбран страж по цифрам: текст без цифр безопасен.
- **Доверять промпту, без сверки чисел ответа с результатами.** Меньше кода и ложных отказов. Отвергнуто: модель склонна складывать («всего по двум шоурумам») и округлять, это ровно то, что запрещает инвариант 2. Цена: отказ, если модель переформатировала число; лечится тем, что проценты приходят строками.
- **Adaptive thinking с effort low.** Лучше выбирает инструмент, но при `max_tokens=600` рассуждение делит бюджет с ответом, `max_tokens` станет частой ошибкой. Задача маршрутизации по enum, мышление не нужно.
- **Tool Runner SDK вместо ручного цикла.** Бета, и лимит 3 вызовов, страж и подпись всё равно пришлось бы вешать хуками. STACK.md фиксирует ручной цикл.

## Дополнение после critique (27.09.2026)

Critique диапазона 36bd983..2d9ea8b: все замечания приняты. Решения пользователя:

1. **Страж чисел.** Число извлекается вместе со знаком (`+`, `-`, `−` U+2212; `-` и `−` считаются одним знаком) и «%» (допустим пробел перед «%») и сравнивается с результатами в той же форме: «+15%», «15%», «15» и «−15%» это разные числа. Части дат (день, месяц, год) разрешены только из дат подписи; даты в результатах и в вопросе сравниваются целиком. Числительные словами: системный промпт их запрещает; словарь `doi`/`două` … `douăzeci` переводит слово в число, и оно проверяется как обычное. `un`, `o`, `unu`, `una` в словарь не входят (артикли); `nouă` тоже не входит: это ещё «новая» и «нам», ложный отказ на каждом «ofertă nouă».
2. **Нет успешного вызова.** Ни одного вызова, отработавшего до конца, и в тексте есть цифры → отказ `blocked_numbers`, как без вызова. Отработавшим считается и вызов с ответом «нет данных» (`NoDataError`: нет снапшота за дату): это ответ инструмента, модель пересказывает его дату. Ошибка аргументов, неизвестный инструмент и превышение лимита вызовов не считаются; их тексты в разрешённые числа не входят.
3. **compare_periods.** `period_a` оцениваемый (обычно более поздний) период, `period_b` база сравнения: в описании инструмента, в описаниях полей схемы и в системном промпте. Инструмент возвращает готовую строку направления из кода, например «august 2026 față de iulie 2026: +17,4%» (процент с одним знаком после запятой, от `metrics.extra.period_delta`); модель её цитирует. Для KPI строки изменения нет, как и раньше.
4. **Дедлайн и сбои.** Общий дедлайн 60 с на вопрос через `asyncio.timeout`, срабатывание = `api_error`. Любое исключение при ответе на вопрос в `answer_in_group` (контекст, снапшоты, модель, инструменты, reply): ответ «Nu pot răspunde acum…», строка `api_error` в `chat_questions` (входит в дневной лимит), алерт в служебный бот.
5. **Тексты.** Все румынские тексты чата из кода переезжают в `templates/`.
6. **Лимиты.** `max_tool_calls`, `max_answer_tokens` и глубина истории конкретных дат в `config/modules.yaml` (`chat`); `max_retries` клиента Anthropic именованной константой.
7. Остальные замечания (сумма потерь через `metrics/`, одноразовые хелперы, WHAT-комментарии, зеркальные тесты, `httpx2` в dev-зависимостях, имя файла описаний инструментов) исправляются как предложено в critique. Описания инструментов живут в `config/modules.yaml` (`chat.tools`), а не в `config/chat_tools.yaml`, как было записано выше.

Коммиты harden: `fix(chat)` страж; `fix(chat)` направление compare_periods, дедлайн, сбои; `refactor(chat)` тексты, лимиты, переиспользование metrics, тесты и комментарии.
