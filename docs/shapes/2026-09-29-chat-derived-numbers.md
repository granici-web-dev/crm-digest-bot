# Shape: производные числа в ответах чата (провалы M6)

Статус: подтверждён 29.09.2026 (раздел «Согласовано»).

## Цель

Ворота M6 «0 чисел не из инструментов»: число, которое естественно назвать в ответе, приходит готовым из инструмента (инвариант 2), а при срабатывании стража группа получает ответ без выдуманного числа, а не отказ.

## Разбор трёх провалов

Текст модели до стража нигде не сохранён: `checked_answer` подменяет его на `UNVERIFIED_NUMBERS_TEXT`, в `ChatAnswer` и в eval его нет. Разбор ниже сделан по результатам тех же вызовов на снапшотах 27.09 и 28.09 (локальный прогон `run_tool`, без Anthropic) и по множеству чисел, которые страж разрешил. Первый шаг craft его подтверждает (см. «Проверка»).

| Вопрос | Результат инструмента | Число | Откуда, вывод |
|---|---|---|---|
| compare-leads-weeks | `period_a` 28.09–29.09 (данные на 28.09): 19; `period_b` 21.09–27.09: 92; `change` −79,3% | «2» | Разница (73), сумма (111), отношение (4,8) не дают 2. Даты подписи разрешают 28, 29, 9, 2026. Остаётся длина неполной недели: «săptămâna curentă are doar 2 zile». Число дней периода модель считает сама по строке `days`. |
| overdue-moaca | `lead_count` 0, `max_days_overdue` null, `missing_followup_date.lead_count` 7 | «1» | Описание инструмента в `modules.yaml`: «lead-urile în Revenire 1/2/3 sau Stand BY». Модель пересказывает его: «7 lead-uri în Revenire 1/2/3…». Первый неразрешённый токен 1. |
| missing-followup-date | `by_manager` содержит 1 и 2, `missing_followup_date.lead_count` 40 | «3» | Та же фраза «Revenire 1/2/3»: здесь 1 и 2 случайно есть в результатах (`Marc Andra` 1, `Raileanu Leon` 2), поэтому первый неразрешённый токен 3. |

Совпадение «1 там, где 1 не в результатах; 3 там, где 1 и 2 в результатах» почти исключает другую причину для двух случаев из трёх. Это два разных дефекта:

1. **Производное число** (compare): модель считает дни периода. Лечится полем инструмента.
2. **Цифра внутри имени mefi** (overdue): «Revenire 2» это имя статуса, а не количество. Инструмент не может «отдать» его как число, не ослабив стража (поле `["Revenire 1", …]` разрешило бы голые 1, 2, 3 во всём ответе). Лечится в страже: известные имена mefi вырезаются из текста до поиска чисел.

## Подход

1. Каждый инструмент отдаёт числа, которые напрашиваются в ответе: разница и направление, число дней, число групп, доли. Считает `metrics/` (доли, разницы) или инструмент (длина списка, дни периода); модель только цитирует.
2. Страж перед поиском чисел маскирует точные имена mefi из конфига: статусы (`status_mapping`), шоурумы, источники, имена консультантов. Сравнение без учёта регистра, только целое имя (`Revenire 2`, не `Revenire`). Описание `overdue_followups` называет статусы полными именами, а результат несёт их списком `statuses`, чтобы модель копировала имя целиком.
3. Одна корректирующая попытка при срабатывании стража вместо немедленного отказа (раздел «Что видит группа»).
4. Промпт: одна строка про отсутствующее число.

## Новые поля результата (все 6 инструментов)

Общее для инструментов с периодом (`period_header`: funnel, manager_kpi, compare_periods, loss_reasons):
- `day_count`: число дней периода; `days_with_data`: дней до `data_as_of` включительно (равно `day_count` у полного периода). Считает инструмент из `period_days` и `snapshot_date`.

| Инструмент | Сейчас | Добавляется |
|---|---|---|
| `funnel` | counts, contracts, kpis | `day_count`, `days_with_data` |
| `manager_kpi` | counts, kpis, targets, meets_target | `targets_met` (сколько KPI в цели), `targets_total` |
| `compare_periods` | value обоих периодов, `change` (% только для счётчиков) | `difference`: абсолютная разница, без знака (73); `direction`: `creștere` / `scădere` / `fără schimbare` (текст из `templates/texts.j2`); `change` дополняется разницей со знаком: «… față de …: −73 (−79,3%)». Для KPI: `difference` в процентных пунктах («2,1 pp»), `direction`, `change` = «… față de …: −2,1 pp»; относительный % для KPI по-прежнему не отдаём. `day_count`/`days_with_data` у каждого периода через заголовок. |
| `loss_reasons` | total, by_reason {имя: n}, by_showroom | `by_reason` становится {имя: {`lead_count`, `share`}} (доля от total, `percent_one_decimal`); `showroom_count` (шоурумов с потерями); в разрезе шоурума доли от его total |
| `overdue_followups` | lead_count, max_days_overdue, by_manager, missing_followup_date | `manager_count` (консультантов с просрочкой); у `missing_followup_date` `manager_count` и `statuses` (полные имена статусов mefi из конфига d3) |
| `untouched_leads` | threshold_hours, lookback_days, lead_count, oldest_age_hours, by_manager | `oldest_age_days` (целые сутки, вниз), `manager_count` |

Где считается:
- `metrics/extra.py`: `period_difference(current, previous)` для счётчиков и KPI (None, если одно из значений None), рядом с `period_delta`. Формула тривиальна, но инвариант 1 требует одного места.
- `metrics/weekly.py`: `LossReasons.reason_share(reason, showroom=None)` (None при total 0).
- `metrics/cockpit.py`: `targets_met` из уже посчитанных `*_meets_target`, если нужно в отчётах; иначе сумма в инструменте. Решение в craft по месту использования (m5 его не показывает, значит в инструменте).
- Длины списков, дни периода, сутки из часов: в `chat/tools.py`.

Не добавляем (отвергнуто): отставание KPI от цели в пунктах у `manager_kpi` (×9 полей, путаница пунктов и процентов, в эталонном наборе нет вопроса); отношение «в N раз» у `compare_periods` (дублирует `change`); итоги по `lead_ids` (модель их не видит, строку ссылок собирает код).

## Что видит группа при срабатывании стража

Сейчас: «Nu pot formula un răspuns exact la această întrebare. Reformulați, vă rog.» вместо ответа; статус `unverified_numbers`, алерт в ops с вопросом, инструментом и числом. Пользователь не знает, что именно не так, и переспрашивает то же самое.

После: цикл один раз отправляет модели сообщение «Numărul „X” nu apare în rezultatele instrumentelor. Rescrie răspunsul fără el.» (`tool_choice: none`, те же результаты в истории), страж проверяет новый текст. Прошёл: в группу уходит ответ без выдуманного числа, статус `answered`, в ops алерт «страж: повтор, число X» (наблюдаемость без миграции). Не прошёл: прежний отказ и `unverified_numbers`. Стоимость повтора: один раунд, ≈ 8k входных токенов (≈ $0,016), только при срабатывании. Дедлайн 60 с на вопрос прежний.

## Проверка

1. Craft шаг 0, до правок инструментов: `ChatAnswer.model_text` и печать в eval, затем `eval chat --only compare-leads-weeks,overdue-moaca,missing-followup-date` (≈ $0,06). Если текст модели опровергает разбор, shape дополняется до правок.
2. После правок тот же `--only` (≈ $0,06–0,08): 3/3, повторов стража 0 (исправление в инструментах и маске, а не в повторе).
3. Полный прогон (было ≈ $0,51; ожидаю ≈ $0,52–0,55): числа не из инструментов 0 (30/30 по стражу), итог ≥ 27/30, контакты 3/3, медиана ≤ 15 с. Повторы печатаются отдельной строкой; повтор в зачёт ворот не идёт как провал, но каждый разбирается.
Итого ≈ $0,65–0,70.

## Риски

- **Рост результата.** +2–6 полей на инструмент, у `loss_reasons` вложенность by_reason ×2. Оценка +30–150 токенов на результат у большинства инструментов; у `loss_reasons` с разрезом по шоурумам (доли у каждой причины в каждом шоуруме) до ≈ 400 токенов на вход, при ≈ 7,8k входа на вопрос это до ≈ 5%. Поправлено после критики ba9181f, код не менялся. Мерится итогом eval.
- **Больше разрешённых чисел = слабее страж.** Каждое новое поле пополняет множество разрешённых. Поэтому не отдаём список статусов как числа и не добавляем поля «на всякий случай».
- **Повтор маскирует дефекты инструментов.** Отсюда алерт на каждый повтор и отдельный счётчик в eval.
- **Маска имён.** Имя консультанта или шоурума с цифрой (сейчас таких нет) тоже маскируется; это верно: имя не число.
- **Разбор compare по косвенным данным.** Шаг 0 проверки обязателен.

## Альтернативы

- **Только промпт** («не пиши Revenire 1/2/3, не считай дни»): противоречит инварианту 2, повтор дал те же числа при уже строгом промпте.
- **Разрешить цифры имён через поле `statuses` в результате**: проще, но пропускает «3 lead-uri» в любом ответе с этим инструментом.
- **Вырезать предложение с неразрешённым числом вместо повтора**: бесплатно, но в overdue это предложение и есть ответ (с числом 7); группа получила бы бессвязный остаток.

## Согласовано (29.09.2026)

1. Повторная попытка в проде: при срабатывании стража одна просьба к модели переписать ответ без отклонённого числа. Прошёл страж: ответ уходит в группу. Нет: прежний отказ «Nu pot formula…». В обоих случаях алерт в ops.
2. Колонку в `chat_questions` не добавляем. Алерт ops содержит отклонённое число, вызванный инструмент и текст ответа модели, обрезанный до 500 символов (ПД в нём быть не может: инструменты их не возвращают).
3. `manager_kpi` отдаёт отставание от цели по каждому KPI в процентных пунктах, со знаком, готовым полем (пересмотр пункта «Не добавляем»).
4. Страж перед проверкой вырезает из текста точные имена из конфига: статусы (включая Revenire 1/2/3), источники (BIFE 2026 и др.), шоурумы, имена консультантов из `managers.yaml`. Список собирается из конфига, не хардкодится. Сравнение с учётом регистра, и после «Data revenire» (без учёта регистра) имя не маскируется: без учёта регистра «Data revenire 3 octombrie» и «data revenire 2 zile» прятали от стража число, стоящее после названия поля (дыра найдена критикой ba9181f, закрыта в harden сессии 40). Тест: «Revenire 2» не разрешает голую «2» в другом месте ответа.
5. Остальное по shape: таблица новых полей для всех шести инструментов, число дней периода, строка в `chat_system.md`.
