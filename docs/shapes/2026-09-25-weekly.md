# Shape: недельный отчёт w1–w4, w8, w12

Статус: подтверждён 25.09.2026, ответы на вопросы в конце.

## Goal

В понедельник 09:00 в группу уходит недельный отчёт: w1 (формат ручного понедельничного отчёта), w2 визиты, w3 воронка, w4 причины потерь, w8 дельта к прошлой неделе и w12 Excel-вложение. Все цифры считает `metrics/weekly.py`, модули только рендерят.

## Два окна недели

Отчёт за неделю Пн D..Вс S читает снапшот за S (`run_report` уже берёт дату от `period.end`).

- **Рабочая неделя (только счёт лидов w1, w12 и «Leads» в w8).** У каждого лида свой рабочий день: время по Бухаресту в [10:00, 19:00) → тот же день, иначе → следующий календарный день. В неделю входят лиды с рабочим днём в [D, S]. Интервал created_at из этого не получается. Входят Вс S−7 [00:00, 10:00), [Вс S−7 19:00, Сб 24:00) и Вс S [10:00, 19:00). Вс S [00:00, 10:00) уходит в понедельник следующей недели. Это расходится с «[прошлое Вс 19:00, это Вс 19:00)» из задачи, см. вопрос 1.
- **Окно недели (всё остальное).** [Вс S−7 19:00, Вс S 19:00) = объединение семи ежедневных окон d1. Визиты, контракты по converted_at и потери недели равны сумме за семь дней, ничего не теряется между неделями.

## Approach

`metrics/weekly.py`: `weekly_window(report_date, time)` (Period), `working_day(created_at) -> date` (векторно по Series), `weekly_lead_frame` (рабочая неделя, без источника Showroom), затем функции модулей. Каждая функция возвращает frozen dataclass. Готовые формулы не дублируем: w3 = `kpi.lead_counts` + `kpis_from` на окне недели, w8 «оферты» = `daily.transition_flags(sunday, week_ago_sunday, weekly_window)`, контракты считаются по converted_at, как в d6.

- **w1.** `WeeklyLeadTables`: день × шоурум (все шоурумы из config, затем «(fără showroom)» и TOTAL), шоурум × источник, день × шоурум × источник (только для Excel). Колонки источников: только встреченные за неделю, по убыванию итога, при равенстве по алфавиту, «(fără sursă)» последней. Это правило восстановлено по трём образцам июля и сходится со всеми тремя. В Telegram два блока из образца, каждая строка таблицы в своём `<code>`: `split_message` режет по строкам, а многострочный `<pre>` сломал бы разметку.
- **w2.** Лиды с `is_showroom_visit` (тот же флаг, что знаменатель SC), created_at в окне недели, по дням × шоурумам. Сумма w2 не обязана совпадать с суммой Vizita в d1: d1 ещё считает переходы в статус визита по разнице снапшотов.
- **w3.** Лиды, созданные в окне недели, на дату снапшота: LEADS → USEFUL (−IRR) → OFFERS → CLIENTI, L2O, O2C из `kpis_from`. Строка-пометка: оферты и контракты по этим лидам ещё будут расти.
- **w4.** LOST по ключам `LOST.reasons` (порядок из config): status_changed_at в окне недели плюс лиды LOST, созданные в окне с status_changed_at null. По шоурумам и итог.
- **w8.** Лиды (рабочая неделя), визиты, контракты: эта неделя против прошлой, обе считаются по воскресному снапшоту. Оферты считаются только если есть success-снапшот ровно за S−7, иначе «—». Процент изменения; при нуле в прошлой неделе «—».
- **w12.** Модуль `reports/modules/weekly_excel.py` пишет xlsx через xlsxwriter в BytesIO. Листы «Свод день-шоурум», «По дням шоурум-источник», «Шоурум-источник итог» повторяют образец, лист «Lead-uri» строится из `weekly_lead_rows()`. Колонки: id, дата, рабочий день, шоурум, источник, статус, ofertat, консультант. Список колонок задан явно в metrics, чтобы ПД не попали в файл. Текст блока: «📎 <имя файла>». Имя файла `<tenant>_sapt<ISO-неделя>_<год>.xlsx`.

- `src/digest/reports/runner.py`: для weekly грузить снапшот ровно за S−7 (SnapshotMissingError → None). После текста отправлять документы модулей, их message_id дописывать в `report_runs.message_ids` так же после каждой отправки.
- `src/digest/delivery/telegram.py`: `send_document_with_retry(bot, chat_id, document)`, тот же повтор flood wait.

- `templates/`: `weekly_leads`, `showroom_visits`, `weekly_funnel`, `loss_reasons`, `week_over_week`, `excel_attachment`, по `.ro.j2`/`.ru.j2`. Подписи таблиц как в образце (румынские в обоих языках, как у d1), переводятся заголовки и пометки. Названия дней недели RO живут в шаблоне.
- `docs/kpi-definitions.md`: раздел «Недельные окна» (оба окна, правило колонок). Формулы KPI не меняются, ADR не нужен.
- Тесты: `tests/unit/test_metrics_weekly.py`, `test_weekly_render.py` (+ `__snapshots__`), `test_weekly_excel.py`; `tests/integration/test_report_runner.py`: weekly с документом.

## Schema / API changes

Миграций нет. `report_runs.message_ids` уже список, в него попадёт и id документа. Меняются публичные dataclass: `ReportContext` получает поле `week_ago`, `ModuleResult` поле `document` (оба с дефолтом None, daily-модули не меняются).

## Test plan

Unit, seam: публичные функции `metrics/weekly.py`, всё время с явной `ZoneInfo("Europe/Bucharest")`.
- `working_day`: 09:59 → следующий день, 10:00 → тот же, 18:59 → тот же, 19:00 → следующий.
- Границы недели: Вс S 18:59 входит, Вс S 19:00 → следующая неделя, Вс S 09:59 → следующая неделя, Вс S−7 09:59 → этот понедельник, Вс S−7 19:00 → этот понедельник, Вс S−7 18:59 не входит.
- DST: неделя 19–25.10.2026. Вс 25.10 03:30 (время повторяется) → понедельник 26.10; Вс 25.10 18:59 после перевода входит.
- w1: источник Showroom исключён целиком; «(fără showroom)» и «(fără sursă)»; порядок колонок; TOTAL по строкам и колонкам. Синтетический кадр: в репозитории нет полевых данных за июль (в `docs/reference/` только SB KPi.xlsx за май), поэтому цифры образца 13–19.07 в тест не переносим.
- w2, w3, w4, w8: по синтетическому кадру на модуль, ожидаемые числа посчитаны вручную. В w4 проверяется LOST с null status_changed_at. В w8: оферта «—» без снапшота S−7, снапшот S−6 не подходит, при нуле в прошлой неделе «—».
- Рендер RO/RU каждого модуля: syrupy. Числа проверяются явными assert, не снапшотом.
- Excel (openpyxl): имена листов, заголовки, итоги равны итогам `WeeklyLeadTables`, в «Lead-uri» ровно восемь колонок и нет phone/email/name.
- Интеграция (Postgres + фейковый aiogram): weekly-прогон шлёт текст, затем документ, оба id в `report_runs.message_ids`; сбой отправки документа → failed.

## Tradeoffs / alternatives considered

- **Одно окно для всех модулей (рабочая неделя везде).** Отвергнуто: визиты и контракты это не «когда продавец увидел лид», у d1/d6 уже окна 19:00→19:00. Рабочее правило для них разошлось бы с суммой ежедневных отчётов.
- **w3 на рабочей неделе, чтобы LEADS совпадал с w1.** Не совпал бы всё равно: w1 исключает источник Showroom, LEADS исключает PARTNERSHIP и тестовые аккаунты. Переиспользовать `kpi.lead_counts` на Period важнее, чем подгонять.
- **Excel строится в metrics.** Отвергнуто: xlsx это представление. metrics отдаёт таблицы и строки лидов с явным списком колонок, поэтому проверка на ПД остаётся в metrics.
- **Таблицы в `<pre>`.** Отвергнуто из-за `split_message`, см. w1.

## Ответы пользователя (25.09.2026)

1. Правило по лиду: у каждого лида свой рабочий день, неделя = лиды с рабочим днём Пн–Вс. Записано в PLAN и CLAUDE.md.
2. Строка «+N lead fără dată» не выводится.
3. Визиты (источник Showroom) идут отдельным листом «Vizite» с теми же восемью колонками. Суммы «Lead-uri» равны сводным листам.
4. Консультант вне managers.yaml в Excel: «id <n>».
