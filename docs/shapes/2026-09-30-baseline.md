# Shape: команда baseline

30.09.2026. Статус: подтверждён (раздел «Согласовано»).

## Goal

`python -m digest baseline --date YYYY-MM-DD [--out файл] [--compare прошлый-файл]` считает все метрики `docs/baseline-2026-09.md` (A, B, C, D1–D3, F, касания) по снапшоту даты теми же функциями `metrics/`, что отчёты и чат (инвариант 1); с `--compare` печатает «база → сейчас → Δ».

## Approach

Новый модуль `src/digest/acceptance/baseline.py` рядом с `chat_eval.py` и `privacy.py`: он не считает, а только вызывает функции `metrics/` и раскладывает результаты в плоские строки `BaselineRow(id, label, value, unit, period)`. Одна строка = одно число со стабильным `id` (`A1.stand_by`, `B1.scr.2026-08`, `C.Raileanu  Leon.since.scr`), поэтому файл сравнивается построчно без разбора текста. Три недостающие метрики (A1, A7, часть A6) не пишутся в `baseline.py`: две новые функции идут в `metrics/daily_checks.py`, A6 уже есть в m8. Запас считается на `daily_window(date).end`, поток — `month_window(date)` и прошлый месяц из того же снапшота (как m8 и m9: `created_at` и `converted_at` не меняются), консультанты — с `leads_created_from` и за месяц.

**Новые функции (место — `metrics/daily_checks.py`, рядом с d3, те же `manager_names` и возраст статуса):**

- `followup_backlog(lead_frame, period, report_date, config) -> FollowupBacklog(lead_count, with_offer, revenire_due, older_than_days: dict[int, int], by_manager)`. Множество: `category == LOST & is_followup_status` среди `leads_in_period` (то есть причины LOST с `followup_field`, сейчас только Stand BY; ключ причины в коде не пишется). Возраст статуса = `status_changed_at.fillna(created_at)` до конца окна даты, как в `missing_followup_date`. Пороги возраста `[30, 90]` — в `config/kpi.yaml` (`backlog_age_days`), не в коде. `revenire_due` = `data_revenire < report_date` без проверки касания: это не A3 и в документе будет названо иначе.
- `not_taken_leads(lead_frame, period, report_date, config) -> NotTakenLeads(lead_count, older_than_day)`: `manager_names(...).isna()` среди открытых лидов (`ACTIVE`, `ACTIVE_FOLLOWUP`, `UNMAPPED`) из `leads_in_period`.
- `status_changed_at.fillna(created_at)` уже повторён в `missing_followup_date`, `anomalies`, `touch_rows`; с `followup_backlog` это четвёртый раз. Выносится в `status_set_at(lead_frame)` отдельным коммитом `refactor:` до фичи.
- Обе формулы — раздел «Базовая линия» в `docs/kpi-definitions.md`, ссылки из комментариев. Эталон не меняется: прежние формулы и числа не трогаются.

## Формат файла

```
# Baseline 29.09.2026
Снапшот: 29.09.2026 19:00 · команда: python -m digest baseline --date 2026-09-29

| id | Метрика | Значение | Ед. | Период |
|---|---|---|---|---|
| A1.stand_by | Stand BY | 150 | лидов | на 29.09.2026 |
| B1.scr.prev | SCR месяца | 10.9 | % | август 2026 |
| D5.cpl | CPL | — | нет источника | — |
```

Проценты — одна десятая, точка, как `shown_percent`; Δ процентов — в п.п. `id` месяца — `cur`/`prev`, а не дата: при сравнении 31.10 с 29.09 `B1.scr.prev` сравнивает август (на 29.09) с сентябрем (на 31.10), оба месяца через месяц после закрытия. Терминал печатает ту же таблицу. С `--compare`: `| id | Метрика | База | Сейчас | Δ |`, строки только в одном файле получают «—» и идут в конце. ПД нет: ни id лидов, ни контактов; имена консультантов есть.

## Tradeoffs / alternatives considered

- **Считать в `baseline.py` своим pandas-кодом.** Быстрее, но нарушает инвариант 1: число базы разошлось бы с дайджестом. Поэтому новые множества в `metrics/`.
- **Добавить `stand_by` в `LeadCounts`.** Дало бы C и A1 через `lead_counts_by_manager`, но тянет поле в каждый конструктор `LeadCounts`, эталон и шаблоны ради одного потребителя; возраст и «с офертой» всё равно нужны отдельно.
- **Отдельная команда `baseline compare OLD NEW` только по файлам.** Чище для тестов, но в конце месяца всё равно запускается расчёт; `--compare` на той же команде — один вызов. Ядро сравнения — чистая функция над двумя разобранными файлами, тест идёт по двум файлам.
- **Прошлый месяц по снапшоту своего последнего дня (правило чата).** Снапшотов до 25.09 нет; и m8/m9 уже считают прошлый месяц из текущего кадра.

## Риски

- Первый прогон требует `DATABASE_URL` с живыми снапшотами с 25.09; в прошлых сессиях доступа к `.env` не было.
- A5 среднее грузит до 31 кадра; при ~3 000 лидов это секунды, но пропуски снапшотов делают среднее по меньшему числу дней (печатается «N из M»).
- A6 «новых в месяц» по `status_changed_at`: лид, сменивший статус ещё раз, выпадает из месяца (ограничение m8). В документе будет сказано.
- `unmapped` в F — это «без статуса» плюс неизвестные статусы; строка так и называется.
