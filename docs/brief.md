# Sofabelle · CRM Digest Bot — бриф для /rigorous shape

Дата: 24.09.2026 · Владелец бота и токена: Serghei Granici · Клиент: Sofabelle (mefi CRM, bellesofa.meficrm.com)

## 1. Цель

Telegram-бот, который по расписанию присылает в управленческую группу Sofabelle отчёты по данным CRM (mefi) — ежедневно, еженедельно, ежемесячно, ежегодно — и отвечает на вопросы по этим же данным в чате. Каждый отчёт собран из модулей; владелец включает и выключает модули в настройках бота. MVP — каркас со всеми модулями в реестре, включены базовые; остальные добавляются по одному по мере подключения источников.

Аудитория: владелец Sofabelle, директор, Serghei. Одна Telegram-группа, все видят всё. Продавцов в группе нет.

## 2. Источники данных

| # | Источник | Что даёт | Статус |
|---|---|---|---|
| A | mefi REST API `leads:read` | лиды: статус, источник, менеджер, кастомные поля (Showroom, Ofertat, Data revenire, Revenire 1–3, UTM_*), `created_at` / `status_changed_at` / `converted_at` / `last_contact_at`, заметки, контакты, `elimination` | ключ активен (2 ключа), 600 req/min |
| B | mefi сессионный клиент (логин read-only сервисного пользователя → cookies → внутренние endpoint'ы или CSV Export) | Oferte (номер, сумма, дата создания, срок, статус), Contracte (сумма, дата), Facturi (поступления, предоплаты) | разведка не сделана; сервисный пользователь без 2FA нужен |
| C | mefi `calls:read` | журнал звонков, пропущенные | не активирован; после подключения IP-телефонии |
| D | Meta / Google / TikTok Ads API | расходы по кампаниям | доступы даст владелец (Meta BM, Google Ads + developer token, TikTok BC) |
| E | GA4 Data API | сессии по страницам | сервисный аккаунт от владельца |
| F | Excel 2024–2025 | исторические лиды до внедрения mefi (февраль 2026) | файл у Serghei; маппинг колонок отдельно |
| G | Таблица себестоимости | модель × размер × группа ткани → цена продажи и себестоимость | запрашивается у клиента: прайс-лист, калькуляции по моделям, группы тканей с ценой за метр, политика скидок, доставка/монтаж, НДС |
| H | Заметки продавцов (`Informatii`, `Revenire N`, notes) | конкуренты, модели в спросе — LLM-извлечение | этап 2 |

Ловушки источника A (из документации):
- пустой body в `POST /leads/search` возвращает только `lifecycle: active` → всегда передавать `["active","lost","junk"]`;
- `date_field` поддерживает только `created_at | last_contact_at | status_changed_at` — WON за период фильтруется по `converted_at` на своей стороне;
- `status_changed_at` хранит только последнее изменение → нужны ежедневные полные снапшоты, иначе история воронки не восстановится;
- `estimated_value` продавцы не заполняют (null при 0) → деньги только из источника B;
- кастомное `Ofertat` — булево без даты → дата оферты из B (`Data creare`), запасной вариант — смена статуса на Ofertat;
- неверное имя фильтра или значение → 422, не молчаливое игнорирование;
- `search` может отдавать краткие карточки → проверить, нужен ли `GET /leads/{id}` для кастомных полей; при 100 per_page и ~300 лидов/мес. это до 3 запросов + N деталей — в лимит укладывается.

Хранение: собственный Postgres. Ежедневный полный снапшот лидов из A + таблицы из B–G. Все отчёты и ответы в чате читают из Postgres, не из API. Когорты, «месяц к месяцу», год к году — из снапшотов.

| NU A RASPUNS | LOST · NU RASPUNS | |
| A REFUZAT | LOST · A REFUZAT | |
| PRODUS NEPOTRIVIT | LOST · PRODUS NEPOTRIVIT | |
| BUGET | LOST · BUGET | |
| CONCURENTA | LOST · CONCURENT | |
| TIMP | LOST · TIMP | отказ из-за срока производства 1–2 мес.; отдельная причина, не сливать |
| IRELEVANT, SPAM | LOST · IRELEVANT | исключаются из полезных лидов |
| DESIGNER, INFLUENCER | PARTNERSHIP | исключаются из SCR / MQL |

Шоурум — кастомное поле `Showroom` (București / Brașov / Cluj). Визиты в шоурум — `source.name = Showroom`, считаются отдельно от входящих лидов (в понедельничном отчёте Showroom из лидов исключён — сохранить). Полезные лиды = все − IRELEVANT − PARTNERSHIP. Формат ежедневного отчёта продавцов: «Leads Mail/FB/IG» = source ∈ {Site, Mail, Meta ADS}; «Designer/Colaboratori» = status ∈ {DESIGNER, INFLUENCER}; «Alte/Showroom (revenire)» = source = Showroom ∧ status ∈ {Revenire 1–3}.

| Еженедельный | понедельник 09:00 | пн–вс; для счёта лидов — правило рабочего окна 10:00–19:00 с переносом на следующий день, как в ручном понедельничном отчёте |
| Ежемесячный | 1-е число 09:00 | календарный месяц |

## 5. Реестр модулей

Каждый модуль: `id`, отчёт, источники, `enabled`, функция расчёта, шаблон RO/RU. Одна функция — один модуль; те же функции использует режим вопросов.

**Daily:** `d1` отчёт в формате продавцов по шоурумам + итого · `d2` лиды без касания · `d3` просроченные Data revenire · `d4` оферты >14 дней · `d5` аномалии дня · `d6` сравнение с тем же днём неделю назад · `d7` SCR за 30 дней · `d8` мгновенные алерты

**Weekly:** `w1` день × шоурум, шоурум × источник · `w2` визиты · `w3` воронка недели (L2O, O2C) · `w4` причины потерь · `w5` speed-to-lead · `w6` IRR по UTM_Campaign · `w7` пропущенные звонки без лида [C] · `w8` дельта к прошлой неделе · `w9` CPL/CPUL/CPC по каналу [D] · `w10` расход без лидов [D] · `w11` сессии → лиды [E] · `w12` Excel-вложение

**Monthly:** `m1` картинка «итог месяца» [B] · `m2` картинка воронки по шоурумам · `m3` картинка тренда 6 мес. · `m4` SCR с целями · `m5` Manager Cockpit (SCR, CDR, PLR, SC, PFR, ACR, L2O, O2C, IRR, балл SPI, уровень, рекомендация — формулы и пороги из `SB KPi.xlsx`, листы `15_KPI_Definitii` и `02_Setari_Targete`) · `m6` рейтинг по SPI · `m7` SCR по источникам/кампаниям · `m8` причины потерь, динамика · `m9` когортная конверсия · `m10` контракты и средняя сумма [B] · `m11` повторные клиенты · `m12` CPO/CAC [D] · `m13` отдача рекламы [B, D] · `m14` поступления, предоплаты, маржа [B, G] · `m15` реоферты, отмены [B] · `m16` топ продуктов [B, G] · `m17` конкуренты из заметок [H] · `m18` модели в спросе [H] · `m19` Excel + PDF

**Yearly:** `y1` сезонность · `y2` год к году [F] · `y3` шоурум и консультант года · `y4` потери по кварталам · `y5` источники ↑↓ · `y6` бюджет и отдача за год [D] · `y7` контракты, поступления, маржа [B, G] · `y8` конкуренты и модели [H]

**Chat:** ответы на вопросы через те же функции (§7).

## 6. Настройки бота

`/settings` — только для admin по Telegram ID → inline-клавиатура: Daily / Weekly / Monthly / Yearly / Chat → список модулей с ✅/⬜ → таблица `settings` в Postgres. Модуль с неподключённым источником показывается серым с пометкой «нет данных: [источник]», включить нельзя. Также в настройках: язык отчётов RO/RU, время отправки, chat_id группы, пороги (14 дней, 4 часа, цели SCR 10/7/5 %).

Дефолты — в конфиг-файле при первом запуске; дальше только через бота.

## 7. Режим вопросов в чате

Триггер: @упоминание или reply на сообщение бота в группе. Claude с инструментами — функции модулей плюс базовые `funnel(period, showroom)`, `manager_kpi(name, period)`, `compare(period_a, period_b, dimension)`, `loss_reasons(period, showroom)`, `untouched_leads(as_of)`. Модель выбирает инструмент и параметры, инструмент считает по тем же формулам, что отчёты, модель формулирует ответ с периодом и цифрами. Модель не считает сама и не отвечает без вызова инструмента. Нет данных — говорит об этом; вопрос вне данных (прогнозы, общие темы) — отказ с предложением фактов. Персональные данные клиентов не выводятся. Язык ответа = язык вопроса. Все вопросы логируются.

## 8. Служебный бот

Отдельный бот, личка Serghei: ошибки API и сессии B, 429, UNMAPPED, расхождение Clienți ↔ `converted_at`, падение вебхука, время выполнения, сбой отправки, изменение структуры ответа B. Сбой источника не блокирует отчёт: отчёт уходит с пометкой «данные [источник] за сегодня недоступны».

## 9. Безопасность и данные

- Токены и пароль сервисного пользователя — в секретах окружения; `.env` только локально, в репозиторий не попадает.
- Сервисный пользователь mefi: read-only роль, без 2FA, отдельный от директора; скрипт делает только GET и логин.
- В группу — только агрегаты и имена сотрудников; телефоны, e-mail, тексты заметок клиентов не выводятся.
- Проверить ToS mefi на автоматизированный доступ.
