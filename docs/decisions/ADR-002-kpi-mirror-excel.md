# ADR-002 · KPI v1 повторяет SB KPi.xlsx v2.0

Статус: **accepted** (24.09.2026). Формулы — `docs/kpi-definitions.md`, эталон — `tests/fixtures/etalon-2026-05.json`.

## Контекст

Владелец и менеджеры оценивают консультантов по `SB KPi.xlsx` (Sales Performance Index v2.0): экспорт лидов mefi вставляется в `01_Input_Leads`, баллы и рекомендации считает `03_KPI_Agenti`. Бриф (`docs/brief.md` §3) и первая версия `docs/kpi-definitions.md` описывали формулы иначе. Если бот покажет консультанту другой SPI, чем Excel, обсуждать будут расхождение, а не работу консультанта.

## Решение

v1 повторяет формулы workbook один в один: базовые множества, KPI, ступенчатые баллы, штраф IRR, SPI, уровни, цепочку рекомендаций. Пороги из `02_Setari_Targete` переносятся в `config/kpi.yaml` с теми же значениями. Эталон — значения `03_KPI_Agenti` по 6 консультантам.

Причина: это цифры, которым владелец уже верит.

## Расхождения с брифом §3

| Тема | Бриф §3 | v1 (как в Excel) |
|---|---|---|
| Партнёрства | DESIGNER, INFLUENCER — категория PARTNERSHIP, исключаются из лидов и SCR | входят в `LEADS` и в `USEFUL` |
| SC | конверсия визитов в шоурум: клиенты среди визитов | `CLIENTI / SHOWROOM_VISITS`, все клиенты консультанта, без пересечения |
| ACR / «висящие» оферты | ACTIVE без движения > 14 дней по `status_changed_at` | Ofertat DA, не CLIENTI, не IRELEVANT, `last_contact_at` старше 14 дней от даты анализа |
| Деление на ноль | метрика `null`, компонент выпадает из SPI, веса перенормируются | балл считается от 0 (`IFERROR(…, 0)`); в отчёте метрика «—» |
| Контракты | `Clienți` или `converted_at != null` | только статус `Clienți`; `converted_at` — алерт о расхождении |

## Отступления от Excel

- Тестовые аккаунты (`test_account: true` в `config/managers.yaml`) исключаются из `LEADS`.
- Консультант определяется по `assigned_to.id`, а не по тексту `Desemnat` с `TRIM`.
- Категории по `config/status-mapping.yaml`, а не поиском подстроки: SPAM считается IRELEVANT (в эталоне SPAM нет).
- Порог CDR 80 % для третьей ступени зашит в формулу Excel; у нас это `cdr_contact_floor` в конфиге.
- Дефект `01_Input_Leads!AC`: ссылка на пустую `02_Setari_Targete!$B$2` вместо даты в B3 обнуляет ACR у всех. Считаем по дате анализа, как задумано; влияние на эталон описано в `docs/kpi-definitions.md`.

## Последствия

- `config/status-mapping.yaml`: `PARTNERSHIP.excluded_from_leads: true` противоречит решению, поправить в shape `metrics/`.
- Бриф §3 про полезные лиды и визиты в шоурум для KPI не действует; для ежедневного отчёта продавцов остаётся.
- Пересмотреть после месяца эксплуатации отдельным ADR: партнёрства в LEADS, SC без пересечения, ACR по `last_contact_at`, 0 вместо `null` в баллах.
