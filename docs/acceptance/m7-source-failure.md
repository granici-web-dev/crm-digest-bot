# M7: учебный сбой источника (чек-лист)

Ворота: сбой mefi не блокирует отчёт; отчёт уходит с пометкой «date indisponibile», ошибка в служебный бот (CLAUDE.md, инвариант 6). Кода для учения нет: неверный адрес mefi и день без снапшота проходят те же пути, что настоящий сбой.

Условия: временная база из M9, до 19:00 по Бухаресту, отчёт только в тестовую группу.

1. Поднять временную базу: `deploy/restore-drill.sh --keep`. Скрипт печатает `DATABASE_URL=…` временной базы, дальше `<временная база>`.
2. Снапшот при недоступном mefi:
   ```
   DATABASE_URL=<временная база> MEFI_BASE_URL=http://127.0.0.1:9/api/v1 uv run python -m digest snapshot
   ```
   Ожидается код 1 и в ops «Ручной снапшот за … не удался». Адрес только localhost с закрытым портом: внешний хост получил бы API-ключ в заголовке.
3. Отчёт за сегодня без снапшота дня:
   ```
   DATABASE_URL=<временная база> uv run python -m digest report daily --date <сегодня, YYYY-MM-DD> --dry-run
   ```
   Ожидается отчёт в тестовой группе с «⚠️ Date mefi indisponibile: snapshotul CRM din … lipsește» и в ops «Снапшот … отсутствует или failed».
4. Удалить временную базу: `docker rm -f digest-restore-drill`.
5. Записать результат в `docs/acceptance/<дата>-m7-source-failure.md`: дата, время, скриншоты двух сообщений в тестовой группе и двух в ops, итог «пройдено/нет».

Вариант «клиенты недоступны, лиды есть» (сноска Contract Cantitate) требует снапшота после 19:00 с живым mefi и в MVP не входит.
